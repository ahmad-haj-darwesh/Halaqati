## نظرة عامة على المعمارية (Architecture Overview)

### الهدف
تقديم صورة مختصرة عن مكوّنات مشروع **حلقتي** وتدفّقات البيانات الأساسية بين تطبيق الموبايل (Flutter) والباكند (Laravel) ولوحة الإدارة (Filament).

### المكوّنات الرئيسية
- **Mobile (Flutter)**: واجهات المستخدم + استدعاءات API + تخزين التوكن/الدور محلياً.
- **Backend (Laravel API)**: منطق الأعمال، المصادقة/الصلاحيات، إدارة الملفات (صور)، وبناء الاستجابات.
- **Admin Panel (Filament)**: إدارة البيانات والمراجعات والإشراف عبر لوحة ويب.

### الأدوار (Roles)
- **Teacher**: إدارة حضور/تقييم يومي، مشاهدة الطلاب، تحديث ملف الطالب، إرسال الملف للمراجعة.
- **Supervisor**: متابعة الطلبات والزيارات وإصدار قرارات (حسب الصلاحيات).
- **Examiner**: تنفيذ الاختبارات وتسجيل النتائج.

### تدفّقات شائعة

#### تسجيل الدخول وتحديد الواجهة الرئيسية
1) الموبايل يتحقق من وجود توكن محلي.\n+2) عند وجود توكن، يتم جلب الدور أو إعادة جلبه من السيرفر عند الحاجة.\n+3) يتم توجيه المستخدم إلى واجهة رئيسية مناسبة للدور.

#### تحديث ملف طالب (Teacher)
1) الموبايل يجلب بيانات ملف الطالب.\n+2) المستخدم يحدّث بيانات/صورة.\n+3) الموبايل يرسل تحديثاً إلى API.\n+4) الباكند يحدّث البيانات ويرفع الصورة (إن وجدت).\n+5) الموبايل يعرض رسالة نجاح ويعود للواجهة الرئيسية.

#### إرسال الملف للمراجعة (Teacher)
1) الموبايل يرسل طلب “Submit for Review”.\n+2) الباكند ينشئ Submission بالحالة المناسبة.\n+3) لوحة الإدارة/المشرف يتعامل مع الطلب.\n+4) يتم السماح بالتعديل أو قفل الملف بناء على القرار.
